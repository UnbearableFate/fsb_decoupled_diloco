## 已关闭 findings

### High — terminal oracle 把提交拓扑误当成 admission 屏障

- 位置：`scenario_supervisor._authority_evidence`、`tools.summarize_runs._parse_full_protocol_run`。
- 问题：3+3+2 或启动较慢时，global target 可以由已 admitted quorum 正常完成；要求终态一定存在八个 learner 会把正常提前关闭判为失败。
- 处理：区分“提交八个 job”和“进入 terminal scope 的 contributor”；仍严格拒绝外部 actor，并要求每个 version 恰好四个 200-step applied update。
- 证据：四个 admitted contributor 的 mutation/acceptance tests 已覆盖。

### High — baseline 与 normal 可以错误绑定不同正式源码

- 位置：standalone baseline source artifact/health、`scenario_supervisor._append_summary`、`tools.summarize_runs.build_comparisons`。
- 问题：只记录 commit 或从全局 summary 任取 baseline，无法证明三个 gate 来自同一 source fingerprint；历史 baseline 还可能阻断新 target。
- 处理：baseline 保存并健康检查完整 canonical clean source identity；normal 只选择 commit 和 fingerprint 均等于当前 run 的单个 DDP 与 periodic baseline；模型、数据、优化器和八 contributor topology 继续参与比较身份。
- 证据：source divergence、topology mismatch、stale-target baseline 过滤 tests 已覆盖。

### High — replacement 只证明同 stream 接替，未证明从启动时最新版本训练

- 位置：`scenario_supervisor._authority_evidence` learner-fault oracle。
- 问题：更高 stream/placement epoch 只能证明 ownership succession，不能证明 replacement 的训练 base 不落后于 admission 时已提交的 latest version。
- 处理：以 `learner_instances.admitted_at` 和 logical `global_versions.committed_at` 求 admission-time latest，并要求 successor 的首个 update `base_global_version` 不低于该版本。
- 证据：stale-base mutation 会按预期失败。

### Medium — baseline 子提交没有显式传递已解析的项目根目录

- 位置：`torch_ddp_baselines/scripts/miyabi/submit_5000steps.sh`。
- 问题：经 experiment04 one-line wrapper 从仓库外目录调用时，PBS job 可能退回不正确的 `PBS_O_WORKDIR`，随后加载错误配置或源码。
- 处理：两个 qsub 均显式传递已验证的 `PROJECT_ROOT`，并拒绝 `qsub -v` 不支持的字符。

### Medium — supervisor timeout 与 40 分钟 PBS 预算余量过小

- 位置：experiment04 submit/PBS/supervisor CLI。
- 问题：旧 2,100 秒 terminal wait 再叠加 60/90 秒 fault timeline、scheduler FINISH wait 和 evidence 收集，可能接近 2,400 秒硬 walltime。
- 处理：内部 wait 收敛到 1,800 秒，保留 fault 注入、terminal teardown、scheduler history 和 artifact 写入余量；没有放宽任何产品 oracle。

## 架构与剩余风险

当前实现保持一个 experiment04 launcher、两个当前 Full Protocol config、一个 baseline config 和一个统一 summarizer，没有兼容分支或旧入口。Supervisor 是场景时序与 scheduler ownership 的唯一 owner，SQLite/immutable artifacts 是行为 oracle，日志只作诊断。

剩余风险属于正式实验需要验证的运行时事实：8-node baseline 的实际 40 分钟预算、GPT-2/WikiText 缓存与 NCCL 环境、七场景在真实 scheduler 下的时间边界，以及 normal 的 loss/time 30% comparison。它们不能由单节点测试替代，但当前 launcher、identity 和 oracle 已具备让失败可归因的证据。
