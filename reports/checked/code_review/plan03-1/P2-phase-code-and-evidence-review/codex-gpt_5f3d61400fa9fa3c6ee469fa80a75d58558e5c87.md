## Findings

### P2-F1 — High — the module manifest can claim per-module coverage without a test for that module

`tests/module_coverage.json` maps groups of many surfaces to groups of tests,
while `test_module_coverage_manifest.py` checks only that every surface appears
once and that every named test file exists. It never establishes which test
owns which surface or whether the named test exercises that surface's public
boundary. This creates concrete false coverage. For example,
`fs_diloco/tools/analysis.py` is grouped with six unrelated tools, but none of
the listed tests imports or calls `summarize_run`, `assert_summary`, its parser,
or its CLI. The public dispatcher in `fs_diloco/cli.py` and the manual-close CLI
in `fs_diloco/tools/request_terminal_close.py` likewise have no behavioral
dispatch/argument tests; the current manifest only points at broad architecture
or storage tests.

This contradicts `UNIT-01`, which requires every retained module to have a
focused unit or static contract test at its public behavior boundary. A passing
inventory equality assertion is not evidence for that stronger requirement.

Required remediation: make coverage ownership exact per retained surface, add
focused behavioral tests for the uncovered public CLI/inspection boundaries,
and make the manifest validator reject group-level cross-product claims. A
surface may cite an indirect test only when that test has a specific assertion
for the named boundary.

### P2-F2 — High — the phase PASS evidence is absent from the frozen target and does not implement the gate artifact contract

The three P2 PASS logs are ignored by `**/artifacts`, are not tracked in target
`5f3d614...`, and the frozen target predates the full-suite PASS. Consequently a
read-only review snapshot cannot open the evidence paths named by the later
workflow state/progress records. The logs are also ad-hoc stdout captures, not
the required artifact-schema object: they omit the explicit command, ordered
source scopes/fingerprint, interpreter/package provenance, requirement
ownership, errors, pre-existing evidence paths and cleanup projection.

This violates workflow sections 4.3, 5.2, 10.1 and the plan's frozen
`artifact-schema.md`. The test count alone cannot promote `UNIT-01` or
`HARNESS-01` through a phase evidence review.

Required remediation: implement and unit-test one current atomic P2 validation
artifact producer, rerun the focused/static and complete-suite commands in a
main-agent-held one-node allocation, and track the compact raw logs plus the
validated structured PASS artifact in the new phase target. The artifact must
bind the exact clean source identity and both P2 requirement IDs.
