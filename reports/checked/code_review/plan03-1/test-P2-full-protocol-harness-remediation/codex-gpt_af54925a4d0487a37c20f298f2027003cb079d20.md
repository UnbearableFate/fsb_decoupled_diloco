## Finding closure review

### C1 — aggregate Checker acceptance

The new fixture uses the current initializer, descriptor/config identity,
fresh static authority schema and public fenced authority commands to create
one contributor, one exact local cycle, genesis plus one committed successor,
balanced receipt/proposal/token rows, terminal acknowledgement, finalized
authority, a released leader epoch, fixed plus immutable terminal controls,
valid actor attestations, exact PBS node identity, source capture and a valid
audit batch. The Checker runs as a subprocess over those durable inputs and
must produce a schema-valid PASS.

Eight separately rebuilt fixtures mutate source capture, resolved config,
epoch lifecycle, attested topology, terminal authority, audit integrity, exact
workload and publication identity. Each must change acceptance to FAIL. This
exercises the aggregate projection and avoids relying on actor exit codes.

### C2 — FAIL versus BLOCKED

The only implicit BLOCKED preconditions are an unavailable run root or missing
run completion marker. An explicit PBS early-exit reason is also BLOCKED
because durable validation never began. Once a completed run exists, every
config/schema/JSON/audit/authority/identity exception is a FAIL artifact. Both
paths share one validated artifact schema and always set cleanup ineligible.

The boundary is intentionally narrow: it does not infer product correctness
from exception type, and it does not call a partial/corrupt run an unavailable
run merely because later evidence is malformed.

### C3 — epoch lifecycle

The current harness has exactly two registered epoch shapes: normal is one
durably `released` epoch with no successor; takeover is an `expired`
predecessor linked to one durably `released` successor. Counts other than one
or two are rejected during CLI parsing. The Checker still requires a successor
publication and rejects stale publications after the successor boundary.

### C4 — retained surface inventory

`tests/module_coverage.json` maps all 80 current Python/SQL/config/Miyabi
surfaces exactly once to named existing boundary tests. The architecture test
reconstructs the current inventory and rejects missing, extra, duplicate or
dangling mappings. Package declarations are tested as exported/dependency
boundaries rather than mislabeled as behavioral modules.

### A1/A2/A4 — corroborated advisory gaps

The PBS wrapper now rejects an existing evidence target and installs an EXIT
trap before allocation execution. If allocation or Checker execution exits
without publishing evidence, the same Checker atomically emits a structured
BLOCKED artifact with the original gate identity. Existing FAIL/PASS artifacts
are never replaced.

The fault-seam unit test verifies renewer quiescence, outside-transaction
assertion, exact marker fields, SIGSTOP ordering and the post-resume assertion.
A real `LeaderAuthority` transaction proves the public fault assertion fails
closed. The obsolete dynamic multi-node scenario registration was removed;
dynamic membership remains one current product mode with focused unit tests,
while plan03-1 registers only the two static 4+1 fault scenarios.

## False-pass / false-fail and identity review

- A PASS still requires clean source identity, current config/schema, exact
  workload, terminal authority, balanced ledger, immutable object hashes,
  attestation/PBS topology and eligible cleanup.
- Diagnostic FAIL/BLOCKED artifacts cannot become PASS because their config,
  protocol and workload identities are null and cleanup is ineligible.
- The fixture does not copy the Checker's acceptance formula; it drives product
  mutation APIs and then mutates independent durable inputs.
- Exact scheduler hostname equality remains deliberate. No lossy short-name
  alias is introduced.
- The positive fixture traverses actor-attestation and audit-batch validators;
  corrupt JSON/hash/schema paths are caught before a false PASS.
- Epoch lifecycle checks are derived from the two registered scenarios, not a
  permissive list supplied by the run under test.
