## Verdict-relevant findings

### F-1 — Medium — No structured FAIL/BLOCKED gate artifact when the allocation/mpirun stage fails before the Checker runs

Evidence: `scripts/miyabi/run_full_protocol.pbs:39-59` runs `run_full_protocol_allocation.sh` under `set -eEuo pipefail`, then invokes the Checker only after the allocation returns 0. `check_full_protocol_run.py:1100-1107` only produces `_blocked_artifact` when the Checker itself executes. `run_full_protocol_rank.sh:185-194` and `96-114` fail the rank with `exit 1` (fault boundary not reached, learner completed before injection), which aborts `mpirun` and the allocation script; the `ERR` traps (`run_full_protocol.pbs:11`, `run_full_protocol_allocation.sh:3`) only echo to stderr. Net effect: for a legitimate product fault mid-run (precisely the failure mode the fault scenarios exercise, e.g. primary syncer exits before the registered boundary), no structured gate artifact (`status: FAIL/BLOCKED`, cleanup projection, failure class) is ever written; only PBS exit code + logs remain. This undercuts HARNESS-01's "expected failure classification" and workflow §7.2's "structured Checker result, not just PBS exit code".

Impact: FAULT-4L1S-01/HARNESS-01 — failure classification degrades to exit-code + log inference; the workflow §10.2 distinction between `product-valid-failure`, `test-harness-failure`, `infra-invalid-run`, and `source-blocked` cannot be machine-differentiated for the most common fault-scenario failure mode.

Remediation (no compatibility layer): in `run_full_protocol.pbs`, install an `EXIT`/`ERR` trap that invokes the Checker with an explicit `--force-blocked` mode (skip `validate_run`, reuse `_blocked_artifact`, `errors=[run failure + captured stderr tail]`, `cleanup.eligible=False`) so a gate artifact is always published, or have the allocation script call a small `record_run_failure` helper on abort.

Missing test: RED — a pytest (shell-level or `subprocess`) that runs `run_full_protocol_allocation.sh`-equivalent with a poisoned actor (e.g., `PYTHON_BIN=/bin/false`) and asserts a structured JSON artifact with `status == "BLOCKED"`, non-empty `errors`, and `cleanup.eligible is False` is produced with the same schema the successful path uses.

### F-2 — Medium — The fault-injection seam and the harness fault logic are not unit-tested

Evidence: `fs_diloco/runtime/syncer.py:64-109` (`_pause_candidate_at_fault_boundary`: marker content `sqlite_transaction_active=False`/`lease_renewer_quiesced=True`, `assert_outside_transaction`, then `SIGSTOP`) and `fs_diloco/runtime/syncer_entrypoint.py:49-60` (`_LeaseRenewer.quiesce_for_fault_injection`) have **no** focused test. `rg "FAULT_PAUSE|fault_boundary|quiesce_for_fault" tests/` returns only `tests/harness/test_full_protocol_harness.py:247-271`, which is pure string matching (`"FS_DILOCO_FAULT_PAUSE_AFTER_COMMITTED_VERSION=2" in rank_runner`, `"kill -KILL \"$primary_pid\""`). The rank script's fence-poll / marker-wait deadlines (`run_full_protocol_rank.sh:74,183-197`) are likewise only exercised at 5-node runtime. Workflow §7.2 and §10 rule ("harness 也是产品代码"; failures findable before qsub must not be found by formal allocation) require this seam to be unit-verified before the first allocation.

Impact: HARNESS-01 / FAULT-4L1S-01 — a regression in the seam (marker written with wrong transaction claim, SIGSTOP omitted, renewer not actually excluded, deadline bounds wrong) would only surface as a failed 5-node fault run (see F-1: no structured artifact), costing an allocation and contaminating failure counting.

Remediation: add a focused unit test driving `_pause_candidate_at_fault_boundary` with a `LeaderAuthority` inside/outside a transaction and a fake `renewer`; assert marker fields exactly, that `os.kill(SIGSTOP)` is the last side effect (monkeypatch `os.kill`), and that `assert_outside_transaction` raises when invoked inside an open SQLite transaction. Add a shell-level static test that the rank script's fault branches fail closed on missing PBS vars and on boundary timeouts.

Missing test: RED — mutation: replace `assert_outside_transaction()` with a no-op and assert the seam test fails; and a mutation that writes `"sqlite_transaction_active": True` into the marker asserts the test fails.

### F-3 — Low — Topology identity is compared without normalization across `PBS_NODEFILE` and `socket.gethostname()`

Evidence: `check_full_protocol_run.py:103-110` (`_pbs_nodes` = stripped raw nodefile lines) vs `fs_diloco/core/run_descriptor.py:229` (`hostname=socket.gethostname()`) compared at `check_full_protocol_run.py:710` (`set(nodes) != hosts`) and `711` (`len(nodes) != expected_hosts`). If the nodefile uses FQDN/trailing-dot form and `gethostname()` returns short form (or vice versa), a fully valid run false-fails the topology oracle. No unit test pins the comparison.

Impact: FORMAL-8L1S-01/FUNC-4L1S-01 — false-fail risk on a correct run purely from hostname representation; also `test_checker_parser_freezes_topology_workload_and_fault_oracles` does not exercise `_pbs_nodes`/host comparison at all.

Remediation: canonicalize both sides (strip trailing dot, lowercase, or compare after `socket.getfqdn`-consistent normalization) in the Checker before `set()` comparison; keep one owner for hostname canonical form.

Missing test: RED — feed `_pbs_nodes` a nodefile with `"node1.fqdn.example."` and a fake attestation with `"node1"`; assert the canonicalized comparison passes while the raw comparison fails.

### F-4 — Low — Dynamic-membership fault oracles have no end-to-end validation path

Evidence: `check_full_protocol_run.py:518-521` hard-rejects non-static descriptors, and `410-414` constructs a static `StaticMembershipScope` from `expected_contributors`; `configs/full_protocol_dynamic.yaml` is referenced only by `docs/configuration.md:30`; `reports/DOING/plan03-1/test-ladder.md:7-15` contains no dynamic gate. Yet `identity-authority.md:55-70` registers `F-DYNAMIC-CAPACITY` as a frozen fault scenario and plan03-1 §过程7 names "节点状态动态变化容错". The requirement matrix pins `FAULT-4L1S-01` to static replacement + syncer takeover, so this is not a matrix violation, but the only multi-node Checker cannot accept the dynamic membership mode it is designed to validate at unit level.

Impact: identity-authority.md F-DYNAMIC-CAPACITY oracles (reservation/launch/admission identity chain, single current fence, bounded pending drain) are unverifiable beyond unit tests; a regression in dynamic scheduler/lease interplay would not be caught end-to-end.

Remediation: either add a dynamic-mode branch to the Checker that mirrors the static path against `full_protocol_dynamic.yaml`, or explicitly record in `identity-authority.md`/matrix that F-DYNAMIC-CAPACITY is a unit-only scenario for this plan and remove it from the frozen runtime scenario list (no compatibility shim).

Missing test: RED — a checker-level mutation test asserting that a dynamic-descriptor run is rejected with a specific error today (pinning the current contract), replaced by a passing assertion once a dynamic validation branch exists.

## Question-by-question assessment

1. **Requirement → assertion/oracle mapping.** Every matrix row maps to concrete assertions: UNIT-01/HARNESS-01 → 40+ test modules; FUNC-4L1S-01/FAULT-4L1S-01/FORMAL-8L1S-01 → `check_full_protocol_run.py` raw query-only SQLite reads, immutable object hash checks, merged hot+archived history (`_audit_rows`+`_merge_history_rows`, lines 468-491), attestation/PBS/nodefile topology, token-balance cross-checks, terminal ack/binding fences. `finalize_terminal` (authority.py:4723-4744) and the Checker independently require zero pending/outstanding. Workload formula (`per_update_tokens = inner_steps×grad_accum×micro_batch×block_size`, checker:631-637) matches the learner cursor/step accounting (learner.py:528-544, token_accounting.py). Gaps: F-1/F-2.

2. **False-pass.** The Checker does not reuse production mutation logic; it re-derives from raw rows and independent anchors. Token balance is cross-checked against `receipt_processed` and `expected_direct` (lines 669-686), so a self-consistent under-count cannot pass. Archive incompleteness fails `adjudicated_processed == receipt_processed`. Path/symlink escapes are rejected via `_protocol_file`/`_require_immutable_file` (tests at test_full_protocol_harness.py:154-203). Identity confusion is fenced: receipt paths are incarnation-namespaced (`cycle_receipt.py:49-55`), proposals rejected on stale fence, source/config/descriptor/authority identities cross-checked 4-way. The `_token_balance` omits `hard_crash_gap_tokens_upper_bound`, which is correct because gap tokens are never added to `adjudicated_processed` (authority.py:5160-5189); but no unit test documents this, so a future accounting change could silently break the oracle — folded into F-2 as a missing characterization test.

3. **False-fail on correct run.** Verified safe: maintenance archiving (only at terminal force-tick here, checkpoint reconstructs hot+archived), takeover lifecycle (namespace receipt isolation; successor re-acks via `_ingest_proposals`; lease-expiry wait 15s ≪ candidate_wait 30s ≪ 60s learner barrier timeout), replacement lifecycle (namespace receipt paths prevent collision; resume from durable progress; killed attempt cannot mutate), terminal behavior (finalize requires all acked; hard-crash path cannot be triggered by these scenarios). Residual risks: F-3 (hostname normalization), F-1 (fault-scenario failure yields no artifact), and the replacement kill point is an arbitrary SIGTERM point — the design is resilient to it, but it is not deterministically pinned (Low; no separate finding).

4. **Coverage proportionality.** Static (SURFACE/CONFIG/SCHEMA/CLEAN/ARCH), success/failure, crash/restart (`test_run_initializer` fault hooks, `test_authority_operational` commit-boundary rollback at 228, `test_leader_authority_commands`), takeover (`test_terminal_service:300` preclose-cutoff successor takeover, `test_authority_operational:1139` uncertainty across leader change), replay/idempotency (`test_leader_authority_commands:62`), generated state machines (`test_state_machine`, `crash_matrix` markers) are all present and proportionate. Gap: the fault-injection seam itself (F-2).

5. **Identity canonical, single owner.** Source (commit+dirty+scopes+fingerprint), config sha, descriptor self-sha, schema version+DDL sha, run ID, static learner IDs (`learner_%03d` everywhere), epoch/owner lease token, receipt/proposal object IDs, PBS job ID (raw `PBS_JOBID` both at attestation time and at checker time — no normalization skew), command IDs (content-hashed), version/predecessor chain — each has one owner and is checked. PBS-ID normalization (`pbs_scheduler.normalize_job_id`) is unit-tested for the dynamic path. Only hostname canonical form is loose (F-3).

6. **Failure-class distinction.** The Checker distinguishes BLOCKED (precondition/invalidity) from FAIL (valid run, wrong authority) from PASS; `_blocked_artifact` records `cleanup.eligible=False`. But the allocation-abort path yields no artifact at all (F-1), so product/harness/infra differentiation is not guaranteed for mid-run faults.

7. **Walltime / fail-fast / retention.** `00:15:00` default ≥ the 10-minute floor and consistent with the halved 60×20→50×10 evidence basis; the 5-node fault runs (15s lease wait + 30s candidate wait) fit comfortably. Fail-fast ordering is sound (topology/count checks in `run_full_protocol_allocation.sh:24-33`, descriptor count at 78-81, PBS group checks). `clean_run.py` is conservative and evidence-bound (PASS-only, exact run below `runs/`, live-reference rejection, symlink/no-follow unlink, manifest `require_new`, inode/size/mtime revalidation) and is unit-tested (test_clean_run.py). Artifact retention rules (workflow §16) match.
