## Finding P3-TAT-001 — High — zero-work terminal paths are rejected

Observed fact: `fs_diloco/storage/authority.py:4738-4742` treats a missing
`token_rollups` singleton as schema corruption. The current ledger deliberately
creates that row on the first cycle receipt, while
`AuthorityRead.token_ledger_summary()` defines an absent row as an all-zero
ledger. Genesis alone therefore has a valid zero direct-applied total without a
physical rollup row.

Concrete counterexample: the current
`test_terminal_zero_cycle_ack_requires_no_receipt_and_preserves_zero_gap` path
commits genesis, closes with `final_cycle_seq=0`, and finalizes without ever
ingesting a receipt. The frozen implementation now raises
`AuthoritySchemaError` instead of publishing a valid terminal total of zero.
The same regression affects all-hard-crash-before-first-receipt paths.

Violated invariant: terminal accounting must use the durable all-history
ledger semantics without changing valid zero-work terminal behavior. Absence
of the lazily materialized singleton is the canonical zero ledger, not evidence
of corruption.

Required remediation: interpret an absent rollup row as
`direct_applied=direct_outstanding=0` inside the finalization transaction,
while continuing to reject nonzero outstanding work. Extend the zero-cycle
test to assert that the persisted terminal applied total is exactly zero. Keep
the archive regression and synchronized Checker mutation unchanged.
