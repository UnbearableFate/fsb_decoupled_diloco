### FSD-H1 — `Critical` — UNIT-01/HARNESS-01 are certified by a process exit status, not a durable oracle

**File/line evidence**
- `scripts/miyabi/run_validation_suite.py:229-262` — each step records only `{name, argv, returncode, elapsed_seconds}`.
- `scripts/miyabi/run_validation_suite.py:187-196` — `PASS` acceptance predicate is `any(step.get("returncode") != 0 …)` plus source cleanliness.
- `reports/DOING/plan03-1/artifacts/20260810-192000_p3-checker-remediation-validation.json` — the published artifact's `metrics.steps` contains four objects, each with `"returncode": 0` and **no collected/passed/failed/skipped counts**.
- `reports/DOING/plan03-1/artifacts/20260810-192000_p3-checker-remediation-validation.log:21,35` — `119 passed in 12.38s` / `505 passed in 23.89s` exist **only in the free-text raw log**.
- `reports/DOING/plan03-1/requirement-matrix.csv:7-8` — `UNIT-01` and `HARNESS-01` are `status=complete`, with this artifact named as required evidence.

**Violated requirement/invariant.** `reports/DOING/plan03-1/artifact-schema.md:60-62`: *"PBS exit status and actor logs are diagnostic fields. Durable SQLite rows, immutable object hashes, contributor fences, terminal acknowledgements, and scheduler history are the success oracles."* The review packet repeats this: *"Do not treat a passing test count or PBS exit status as sufficient proof."* The only machine-checkable success oracle for the two `complete` requirements is `subprocess.returncode == 0`.

**Concrete counterexample (inferred, mechanism observed).** Add `collect_ignore_glob = ["*"]`-style narrowing, an `-k` filter in `addopts`, a module-level `pytest.skip(allow_module_level=True)`, or an import guard that turns `tests/storage/` into skips. `pytest -q` then reports e.g. `380 passed, 125 skipped` and exits **0**. `run_validation()` sets `status = "PASS"`, `_validate_artifact` accepts it (no count is inspected), and the tracked artifact is byte-identical in every field a reader can check. The 125 silently-skipped modules include every authority/fencing/terminal test. FSD-M3 below is a live instance of exactly this failure mode already present in the suite.

**Required remediation.** Make the artifact carry the machine-checkable result, not the exit code: run pytest with `--junitxml=<path>` (or `-p no:cacheprovider` + `--result-log` equivalent), parse the XML, and record `collected`, `passed`, `failed`, `errors`, `skipped`, `xfailed`, `xpassed` per step in `metrics.steps[i]`. Extend `_validate_artifact` so `PASS` additionally requires `failed == errors == 0`, `skipped == 0` (or an explicit, enumerated, justified skip allowlist), and `collected >= <frozen expected count>`. Add the junit XML to `evidence_paths`.

**Smallest missing test / durable oracle.** In `tests/harness/test_validation_suite.py`, add `test_validation_pass_requires_nonzero_collected_and_zero_skipped`: drive `run_validation(steps=…)` with a synthetic step whose junit output reports `collected=0` and separately one reporting `skipped=3`, and assert both produce `status != "PASS"` and a specific error string. ### FSD-H2 — `High` — The checker cannot detect an *unregistered* static learner replacement, so a fault run can be certified as the fault-free gate

**File/line evidence**
- `scripts/miyabi/check_full_protocol_run.py:630-631` — syncer epochs are exactly pinned: `if len(epochs) != expected_syncer_epochs: errors.append(…)`.
- `scripts/miyabi/check_full_protocol_run.py:658-663` — the binding-generation oracle runs **only** `if expected_replaced_learner is not None`.
- `scripts/miyabi/check_full_protocol_run.py:461-464` — `static_binding_history` is queried and projected into `authority.static_binding_history` (line 967) but is **never asserted** when `expected_replaced_learner is None`.
- `scripts/miyabi/check_full_protocol_run.py:626-629` — the only unconditional binding assertion is the `learner_id` set and `status == "terminal"`; `binding_generation` is not constrained.
- `scripts/miyabi/check_full_protocol_run.py:701` — `registered_fault = expected_replaced_learner is not None or expected_syncer_epochs > 1`; when false, the strict one-to-one/adjudication block at 703-740 runs, but nothing pins generation `== 1`.
- `scripts/miyabi/run_full_protocol.pbs:31,59-61` — `EXPECTED_SYNCER_EPOCHS` and `EXPECTED_REPLACED_LEARNER` are free operator environment variables; neither is cross-validated against `FS_DILOCO_FAULT_SCENARIO` (line 41), which is passed independently to `run_full_protocol_allocation.sh:103` → `run_full_protocol_rank.sh:13`.

**Violated requirement/invariant.** `identity-authority.md:12` (*"Static learner … contributor-generation fence … Authority owner: descriptor scope and fenced admission transaction"*) and `FAULT-4L1S-01`'s verification clause (*"Pre-registered process/PBS fault injection; successor fence/epoch and authority rows are durable oracles"*). Pre-registration is only meaningful if the checker rejects a run whose durable authority disagrees with the registration. It does so for epochs and does not for contributor fences.

**Concrete counterexample.** Submit `run_full_protocol.pbs` with `FS_DILOCO_FAULT_SCENARIO=learner_replacement`, `EXPERIMENT_ID=p3-functional-normal`, and `EXPECTED_REPLACED_LEARNER` unset (its default). `run_full_protocol_rank.sh:242-243` executes `launch_replaced_learner 0`: `learner_000` is SIGTERM'd, a replacement authorization is published, and a successor is admitted at `binding_generation = 2` with a `static_binding_history` row `final_status='replaced'`. The checker is invoked without `--expected-replaced-learner`, so `expected_replaced_learner is None` and `registered_fault` is `False`. Under full quorum (`quorum_min == quorum_max == num_learners`, `configs/full_protocol_static.yaml:16-17`) every committed version still requires all N contributors, so `applied_by_contributor` remains exactly `expected_global_steps` per contributor (checker:688-696), one dropped proposal from the fenced old attempt satisfies `expected_dropped` (checker:729-740), the single epoch is `released`, and every remaining assertion holds. The gate publishes **`status: PASS` for a normal-scenario artifact produced by a fault run**, with `binding_generation: 2` sitting unexamined inside `authority.static_binding_history`.

The symmetric failure also holds: the P3 normal gate has no durable proof that no replacement occurred.

**Required remediation.** In `validate_run`, add an unconditional contributor-fence pin:
```python
expected_generation = 2 if expected_replaced_learner else 1
for row in bindings:
    limit = expected_generation if row["learner_id"] == expected_replaced_learner else 1
    if int(row["binding_generation"]) != limit: errors.append(...)
if {r["learner_id"] for r in binding_history} != ({expected_replaced_learner} if expected_replaced_learner else set()):
    errors.append("durable binding history does not match the registered scenario")
```
Separately, in `run_full_protocol.pbs`, derive `EXPECTED_SYNCER_EPOCHS` and `EXPECTED_REPLACED_LEARNER` from `FS_DILOCO_FAULT_SCENARIO` (a `case` block) rather than accepting them as independent inputs, and fail with exit 2 on any inconsistent combination.

**Smallest missing test.** Extend `test_aggregate_checker_mutations_change_acceptance_to_fail` with a `"unregistered_replacement"` mutation: in the fixture DB, `UPDATE static_contributor_bindings SET binding_generation=2` and insert one `static_binding_history` row, then assert `status == "FAIL"`. This currently passes.

### FSD-H3 — `High` — A resumed or replaced contributor cannot produce a valid graceful terminal acknowledgement

**File/line evidence**
- `fs_diloco/runtime/learner.py:476-479` — on admission the learner restores `cycle_seq`, `previous_receipt_id`, `previous_receipt_sha256` from `admission.resume`, then sets `last_cycle_update_id: str | None = None`.
- `fs_diloco/protocol/data_cursor.py:70-76` — `ContributorResumeState` carries `cursor, last_receipt_id, last_receipt_sha256, next_cycle_seq, stream_epoch`. It has **no** `last_update_id` field.
- `fs_diloco/runtime/learner.py:499-505` — on observing drain, the learner acks with `final_cycle_seq=cycle_seq - 1` and `final_update_id=last_cycle_update_id`.
- `fs_diloco/storage/authority.py:4592-4596` — `acknowledge_terminal_contributor` raises `MembershipFenceError("final receipt promised a proposal; acknowledge it or use hard-crash handling")` when the receipt at `final_cycle_seq` has `proposal_expected` true and `final_update_id is None`.
- `fs_diloco/runtime/services/terminal.py:262-268` — the syncer catches that exception and only emits `terminal_ack_rejected` telemetry.
- `fs_diloco/runtime/services/terminal.py:270-288` — after the drain deadline, `_adjudicate_hard_crashes` force-transitions the contributor to `hard_crash` (`authority.py:4534`).
- `scripts/miyabi/check_full_protocol_run.py:622-625` — the checker requires `{row["state"] for row in terminal_fences} == {"acked"}`.

**Violated requirement/invariant.** `identity-authority.md:32-33`: the F-LEARNER-REPLACE durable success oracle requires *"successor accepted, contributor progresses to terminal ack"*. `FUNC-4L1S-01` requires *"terminal acknowledgements"* as a five-node oracle.

**Concrete counterexample.** `learner_000` completes cycle 3, whose receipt has `proposal_expected=True, planned_update_id=U`; the syncer ingests receipt 3 so `contributor_progress.last_cycle_seq = 3`. The learner process is replaced (`run_full_protocol_rank.sh:106`). The successor is admitted with `resume.next_cycle_seq = 4`, sets `cycle_seq = 4`, `last_cycle_update_id = None`. Before it finishes its first inner loop, the global target is reached and the leader publishes drain (`terminal.py:150`). At `learner.py:499` the successor acks `final_cycle_seq = 3, final_update_id = None`. In `authority.py:4565-4574` this passes the frozen-bound and contiguity checks (`close_last_cycle_seq = 3`, `observed_sequence = 3`), then hits line 4592 and is rejected. Repeated on every drain poll, rejected every time. At `drain_ack_timeout_seconds` the contributor is forced to `hard_crash`, and the checker emits `"terminal contributor acknowledgements are incomplete"` → the entire 5-node run **FAILs despite being correct**.

The same hole applies to any static learner restart under the same logical launch (`_admit_observations_unprotected` replay path, `syncer.py:466-527`), not only to the injected replacement.

**Required remediation.** Add `last_update_id: str | None` to `ContributorResumeState` (`data_cursor.py:70`), populate it in `syncer.py:569-577` and `_resume_from_progress` (`syncer.py:805-812`) from `cycle_receipts.planned_update_id` for `progress.last_cycle_seq` (the value is already durable — `authority.py:4583`), extend the admission-response `resume` field set (`syncer.py:785-791`) and `ADMISSION_RESPONSE_FORMAT_VERSION`, and initialise `last_cycle_update_id = admission.resume.last_update_id` at `learner.py:479`.

**Smallest missing test.** In `tests/runtime/test_terminal_service.py`: ingest a receipt with `proposal_expected=True`, `begin_terminal_close`, then attempt a graceful ack with `final_update_id=None` and assert the current code raises; after the fix, assert a resumed learner's resume state carries the planned update id so the ack is accepted. No test in the repository exercises a resumed contributor's graceful ack — `grep -rn "promised a proposal\|last_cycle_update_id" tests/` returns nothing.

### FSD-M2 — `Medium` — Both registered fault injections make their own "stale mutation rejected" oracle unobtainable

**File/line evidence**

- `identity-authority.md:45-48` — F-SYNCER-TAKEOVER: *"start/retain a second candidate … Durable success oracle: … old token rejected, … no split-brain command receipt"*.

**Violated requirement/invariant.** `FAULT-4L1S-01`'s required evidence names successor fence/epoch **and** the rejection oracles. Two of the four registered durable oracles cannot be produced by the registered injections.

**Concrete counterexample.** After `run_full_protocol_rank.sh:108` (`wait "$learner_pid"`), the generation-1 fence has no live holder. No `admission_rejected` disposition, no `MembershipFenceError` command record, and no `proposal_observations` row with a stale-fence disposition will exist in the P3 evidence. "Old-fence mutation rejected" and "no split-brain command receipt" are therefore vacuously satisfied — the strongest single claim of the fault gate rests on evidence the harness structurally cannot generate.

**Required remediation.** Either (a) amend `identity-authority.md` to demote those two oracles to unit-level (they *are* covered — `tests/storage/test_static_contributor_binding.py`, `tests/storage/test_leader_authority_commands.py`) and record that the multi-node gate proves fence advancement and commit exclusivity only; or (b) make them obtainable: for the learner, use `SIGSTOP` instead of `SIGTERM`, request the replacement, admit the successor, then `SIGCONT` the old attempt and assert its next fenced write is rejected; for the syncer, start the second candidate concurrently (`syncer_entrypoint.py:189-198` already polls `LeaseUnavailableError` until `candidate_wait_seconds`) so the successor is genuinely racing at the moment of the kill. Option (a) is the smaller change and is honest; option (b) is what the document currently claims.

**Smallest missing durable oracle.** If (b) is chosen, have the checker require at least one durable rejection artifact bound to the superseded fence — e.g. a `control/registration_dispositions/<sha>.json` with `outcome == "rejected"` naming the generation-1 attempt, or a `proposal_observations` row with a stale-fence disposition — rather than inferring rejection from the absence of a bad commit.

## 3. Verified-correct behaviour (no finding)

Recording these because they were the highest-risk hypotheses and each was disproved by reading the code:

- **Hard-crash acknowledgements cannot masquerade as graceful acks.** `authority.py:4534` sets `state = "hard_crash"` (never `"acked"`), the schema constrains the domain (`schema.sql:97`), and `check_full_protocol_run.py:622-625` requires the state set to be exactly `{"acked"}`. `finalize_terminal` (`authority.py:4731-4742`) permits finalization with hard crashes, and the checker correctly rejects it.
- **Receipt-ID collisions across binding generations are unreachable.** `receipt_id = f"receipt-{key}-{cycle_seq}"` (`learner.py:651`) is not generation-qualified, but `_ingest_proposals` reads only the *current* fence's canonical path (`syncer.py:828-830`) and `resume.next_cycle_seq = progress.last_cycle_seq + 1` (`syncer.py:576`), so a successor can only reuse a sequence whose receipt was never ingested.
- **Leader fencing is sound.** `acquire_leader` uses `BEGIN IMMEDIATE` with an expiry-plus-skew check (`authority.py:888-899`), `_command` re-verifies the token before and after the operation (`authority.py:5658, 5671`), and `LeaseSafetyTracker` (`leader_lease.py:73-79`) adds a local monotonic boundary independent of wall clock. `_pause_candidate_at_fault_boundary` correctly holds the renewal lock and asserts no open transaction across `SIGSTOP` (`syncer.py:94-109`).

- **Failure artifacts are not overwritten by retry.** `run_full_protocol.pbs:66-72` publishes `BLOCKED` only when `EVIDENCE_OUTPUT` does not already exist, and line 33-36 refuses to start if it does.

## 6. Summary

The Full Protocol implementation itself is strong: the authority layer is a genuinely single-writer, fenced, command-idempotent design with careful transaction boundaries, and the unversioned-surface convergence is nearly complete. The problems are concentrated in the **evidence chain**, which is precisely what plan03-1 is currently gating on.

Two requirements marked `complete` rest on oracles weaker than the plan's own rules demand: `UNIT-01`/`HARNESS-01` are certified by `pytest` exit code with no test counts in the durable artifact (FSD-H1), while the checker logic that will decide `FAULT-4L1S-01` has never been executed against a fixture (FSD-H4). The checker pins syncer epochs exactly but leaves contributor binding generations entirely unconstrained for non-fault gates, so a learner-replacement run can be certified as the normal scenario (FSD-H2). And a real protocol defect sits directly on the replacement path: a resumed contributor structurally cannot produce a valid graceful terminal acknowledgement, forcing a `hard_crash` that the checker correctly rejects (FSD-H3).

FSD-H3 is a product bug that should be fixed before the P3 fault runs. FSD-H1, FSD-H2, and FSD-H4 are oracle defects that should be fixed before any P3 or P4 artifact is treated as binding, since each can convert a wrong run into a `PASS`. FSD-M2 requires a decision — either weaken the registered oracle text or strengthen the injection — but should not be left as an unremarked gap between `identity-authority.md` and what the harness can actually produce.

Verdict: CHANGES_REQUIRED
